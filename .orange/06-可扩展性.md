# 06 可扩展性

## 概览

gstack 是**组合架构**，不是插件架构。扩展通过四个主要机制实现：注册命令、添加技能、添加 Host、添加 Resolver 占位符。

---

## 6.1 如何添加新 Browse 命令

**文件: `browse/src/commands.ts`**（单一真相来源）

**步骤:**

1. 将命令名加入适当集合:
   ```typescript
   READ_COMMANDS   // 只读取页面状态
   WRITE_COMMANDS  // 修改页面或导航
   META_COMMANDS   // 浏览器级别操作
   PAGE_CONTENT_COMMANDS  // 包含第三方内容 (触发信封包装)
   DOM_CONTENT_COMMANDS   // 从 DOM 读取 (触发隐藏元素扫描)
   ```

2. 在 `COMMAND_DESCRIPTIONS` 中添加条目:
   ```typescript
   'my-command': {
     category: 'Reading',
     description: 'What it does',
     usage: 'my-command [args]'
   }
   ```

3. 在对应 handler 中实现逻辑（`read-commands.ts` / `write-commands.ts` / `meta-commands.ts`）

4. `bun run gen:skill-docs` 自动从 `COMMAND_DESCRIPTIONS` 生成 `{{COMMAND_REFERENCE}}` 并更新所有 SKILL.md

5. 在 `token-registry.ts` 中将命令归入正确 scope:
   - `SCOPE_READ`, `SCOPE_WRITE`, `SCOPE_ADMIN`, `SCOPE_META`, `SCOPE_CONTROL`
   - 注意: `commands.ts` 的 `READ_COMMANDS` 和 `token-registry.ts` 的 `SCOPE_READ` 是独立的，后者按实际副作用重新分类

## 6.2 如何添加新技能

**文件结构:**
```
my-skill/
├── SKILL.md.tmpl    ← 编辑这个
└── SKILL.md         ← 不要直接编辑（生成的）
```

**SKILL.md.tmpl frontmatter 格式:**
```yaml
---
name: my-skill
preamble-tier: 2        # 1=轻量, 2=标准, 3=需要repo模式, 4=完整
version: 0.1.0
description: |
  一行描述. (gstack)
allowed-tools:
  - Bash
  - Read
  - AskUserQuestion
triggers:
  - my use case
voice-triggers:
  - "my voice trigger"
---
```

**Preamble Tier 选择:**

| Tier | 功能 | 适用技能 |
|------|------|---------|
| 1 | 核心 bash + 更新检查 | browse, benchmark |
| 2 | + 写作风格 + AskUserQuestion + 上下文恢复 | investigate, retro |
| 3 | + Repo mode + Search Before Building | office-hours, plan reviews |
| 4 | 全部 | ship, review, qa |

**生成命令:**
```bash
bun run gen:skill-docs           # 所有主机
bun run gen:skill-docs --host codex  # 只生成 Codex
```

**注册技能:** `setup` 脚本自动发现 `*/SKILL.md.tmpl` 模式并创建符号链接，无需手动注册。

## 6.3 如何添加新 Host

**步骤:**

1. 创建 `hosts/myhost.ts`:
```typescript
const myhost: HostConfig = {
  name: 'myhost',
  displayName: 'MyHost AI',
  cliCommand: 'myhost',
  globalRoot: '.config/myhost/skills/gstack',
  localSkillRoot: '.myhost/skills/gstack',
  hostSubdir: '.myhost',
  usesEnvVars: true,

  frontmatter: {
    mode: 'allowlist',
    keepFields: ['name', 'description'],
    descriptionLimit: 1024,
    descriptionLimitBehavior: 'truncate',
  },

  generation: {
    generateMetadata: false,
    skipSkills: [],
  },

  pathRewrites: [{ from: '~/.claude/', to: '$GSTACK_ROOT/' }],
  toolRewrites: { 'Bash': 'Shell' },
  suppressedResolvers: ['GBRAIN_CONTEXT_LOAD'],

  runtimeRoot: {
    globalSymlinks: ['bin', 'browse/dist'],
    globalFiles: {},
  },

  install: {
    prefixable: false,
    linkingStrategy: 'symlink-generated',
  },
};

export default myhost;
```

2. 在 `hosts/index.ts` 注册:
```typescript
import myhost from './myhost';
export const ALL_HOST_CONFIGS: HostConfig[] = [..., myhost];
```

3. 自动生效: `Host` 类型 union 从 `ALL_HOST_CONFIGS` 推导，无需手动更新。

**已支持主机列表 (hosts/index.ts):**
- `claude` (Claude Code, 主要 host)
- `codex` (OpenAI Codex CLI)
- `kiro`, `openclaw`, `cursor` (IDE 集成)
- `hermes`, `gbrain` (Agent runtime)
- `factory`, `opencode`, `slate`

## 6.4 如何添加新 Resolver（模板占位符）

**文件: `scripts/resolvers/index.ts`**

```typescript
// 注册新 resolver
export const RESOLVERS: Record<string, ResolverFn> = {
  ...existingResolvers,
  MY_RESOLVER: (ctx: ResolverContext) => {
    return `生成的内容，基于 ctx.host, ctx.skill, ctx.skillConfig`;
  },
};
```

**在 .tmpl 中使用:**
```markdown
{{MY_RESOLVER}}
```

**Preamble 组合 (`scripts/resolvers/preamble.ts`):**

每个 tier 是一组 generator 函数的组合。添加新 generator 到相应 tier 即可。

**完整 RESOLVERS 注册表（部分）:**
```
PREAMBLE, BROWSE_SETUP, COMMAND_REFERENCE, SNAPSHOT_FLAGS
BASE_BRANCH_DETECT, SLUG_EVAL, SLUG_SETUP
QA_METHODOLOGY, DEPLOY_BOOTSTRAP
DESIGN_METHODOLOGY, DESIGN_HARD_RULES, DESIGN_REVIEW_LITE
TEST_BOOTSTRAP, TEST_COVERAGE_AUDIT_{PLAN,SHIP,REVIEW}
REVIEW_DASHBOARD, SPEC_REVIEW_LOOP, REVIEW_ARMY
LEARNINGS_SEARCH, LEARNINGS_LOG
BENEFITS_FROM, CODEX_SECOND_OPINION, ADVERSARIAL_STEP
CHANGELOG_WORKFLOW, CO_AUTHOR_TRAILER
GBRAIN_CONTEXT_LOAD, GBRAIN_SAVE_RESULTS  (gbrain host 特有)
```

## 6.5 如何添加新 E2E 测试

**步骤:**

1. 在 `test/helpers/touchfiles.ts` 的 `E2E_TOUCHFILES` 中注册依赖:
```typescript
'my-test-name': ['my-skill/**', 'browse/src/**'],
```

2. 在 `E2E_TIERS` 中分类:
```typescript
'my-test-name': 'gate',     // 安全守护或确定性 → gate (CI 必须通过)
// 'my-test-name': 'periodic', // 质量基准或非确定性 → periodic (每周)
```

3. 在 `test/skill-e2e*.test.ts` 中添加测试，**只提取需要的 SKILL.md 片段**:
```typescript
testIfSelected('my-test-name', async () => {
  const dir = createTempDir();
  // 提取需要的片段，不复制整个 SKILL.md（防止 token 浪费）
  const full = fs.readFileSync(path.join(ROOT, 'my-skill/SKILL.md'), 'utf-8');
  const section = full.slice(full.indexOf('## My Section'));
  fs.writeFileSync(path.join(dir, 'my-skill-SKILL.md'), section);

  const result = await runSkillTest({
    prompt: 'Read my-skill-SKILL.md and do X',
    workingDirectory: dir,
    maxTurns: 10,
    allowedTools: ['Bash', 'Read'],
    testName: 'my-test-name',
  });

  // 可选: LLM judge 评估
  const scores = await judge('output quality', result.output);
  expect(scores.clarity).toBeGreaterThan(3);
}, 120_000);
```

## 6.6 Browser Skills 生态系统扩展

**三层搜索: project > global > bundled**

用户可在 `~/.gstack/browser-skills/` 添加自己的 Playwright 脚本技能，无需修改 gstack：

```
~/.gstack/browser-skills/
└── my-domain-skill.ts   ← 自定义 Playwright 脚本
```

**`browse/src/browser-skills.ts`** 自动发现并注册：
1. `{project}/.gstack/browser-skills/` (项目级)
2. `~/.gstack/browser-skills/` (用户全局)
3. `browse/src/bundled-skills/` (内置)

## 6.7 扩展总结

| 扩展类型 | 文件 | 机制 |
|---------|------|------|
| 新浏览器命令 | `browse/src/commands.ts` | 加入集合 + handler |
| 新技能 | `*/SKILL.md.tmpl` | 模板 + gen:skill-docs |
| 新 Host | `hosts/*.ts` + `hosts/index.ts` | 声明式配置 |
| 新模板占位符 | `scripts/resolvers/index.ts` | ResolverFn 注册 |
| 新 E2E 测试 | `test/helpers/touchfiles.ts` + `test/skill-e2e*.test.ts` | 依赖注册 + 测试实现 |
| 自定义 Browser Skills | `~/.gstack/browser-skills/` | 文件系统发现 |
