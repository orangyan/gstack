# GStack 核心概念速查表

## 🎯 5 分钟速览

### 什么是 GStack？
> 将 Claude Code 转化为 20 人虚拟工程团队的开源软件工厂

### 核心数字
- **23+ 专家角色** - 从 CEO 到 QA 的完整团队
- **100+ 浏览器命令** - ~100ms 延迟，持久化状态
- **3-100x 压缩比** - AI vs 人类团队时间
- **10-15 并行 sprint** - 实际生产力最大值

### 关键技术
- **语言/运行时**：TypeScript + Bun（编译为单个 58MB 二进制）
- **浏览器自动化**：Playwright + Puppeteer + CDP（Chrome DevTools Protocol）
- **AI 模型**：Claude Sonnet/Opus（主要）+ GPT-4（Codex）+ Gemini（可选）
- **存储**：SQLite（cookie）+ JSONL（日志）+ YAML（配置）

## 🏗️ 架构速查

### 守护进程模型
```
CLI（编译的二进制）
  ↓ HTTP POST
服务器（Bun.serve）
  ↓ CDP
Chromium（无头）
```

**性能**：
- 首次调用：~3s（冷启动）
- 后续调用：~100-200ms（热路径）

### 安全层（6 层）
| 层 | 模块 | 功能 |
|----|------|------|
| L1-L3 | `content-security.ts` | 数据标记、隐藏元素剥离、ARIA 正则表达式、URL 黑名单 |
| L4 | `security-classifier.ts` | TestSavantAI ONNX（112MB，本地） |
| L4b | `security-classifier.ts` | Claude Haiku 记录检查 |
| L5 | `security.ts` | 金丝雀（随机令牌在系统提示中） |
| L6 | `security.ts` | combineVerdict（需要 2-of-2 同意） |

### 双监听器隧道架构
| 端点 | 本地监听器 | 隧道监听器 |
|------|----------|-----------|
| `/health` | ✅ 带令牌 | ❌ 404 |
| `/connect` | ✅ | ✅ 速率限制 |
| `/command` | ✅ 全权限 | ✅ 作用域令牌 + 命令允许列表 |
| `/cookie-picker` | ✅ | ❌ 404 |

## 🔒 安全速查

### 环境变量
```bash
GSTACK_SECURITY_OFF=1          # 紧急终止开关
GSTACK_SECURITY_ENSEMBLE=deberta  # 选择加入 DeBERTa-v3（721MB）
```

### 判决阈值
```typescript
BLOCK: 0.85       // 单层分数（如果交叉确认会导致 BLOCK）
WARN: 0.60        // 交叉确认阈值（L4 和 L4b 都 >= 0.60 → BLOCK）
LOG_ONLY: 0.40    // 记录分类器的门控
```

### 侧边栏盾牌图标
- 🟢 绿色：SAFE（所有层 < LOG_ONLY）
- 🟠 琥珀色：WARN（一层 >= WARN，但未交叉确认）
- 🔴 红色：BLOCK（两层 >= WARN 或金丝雀泄漏）
