# 05 数据流

## 概览

gstack 的数据流分三条主要链路：浏览器自动化链路、技能调用链路、E2E 测试链路。

---

## 5.1 用户请求总流转

```
用户在 Claude Code 中输入: /qa https://staging.myapp.com
           │
           ▼
Claude Code 读取 ~/.claude/skills/gstack/SKILL.md
    (由 gen-skill-docs.ts 从 .tmpl 生成，不是可执行文件)
           │
           ▼
Claude 解析 SKILL.md 并理解：
    - 什么工具可用（Bash, Read, AskUserQuestion）
    - 如何调用 browse binary：$B <command>
    - 工作流步骤（qa/SKILL.md 中的分步骤指令）
           │
           ▼
Claude 执行 Bash 工具调用：
    $B goto https://staging.myapp.com
           │
           ▼
Shell 运行编译好的二进制: ~/.claude/skills/gstack/browse/dist/browse goto https://...
           │
           ▼
browse CLI (compiled Bun binary):
    1. 读取状态文件 ~/.gstack/browse.json → {pid, port, token}
    2. 如果服务失活 → 生成随机 token + 随机 port → 启动 server.ts
    3. 向本地 HTTP 发送: POST http://127.0.0.1:PORT/command
       {command: "goto", args: ["https://..."], token: "uuid"}
           │
           ▼
browse server.ts (Bun.serve HTTP daemon):
    1. 验证 Bearer token
    2. 分发到 read/write/meta command handler
    3. 调用 Playwright API
    4. Chromium (CDP) 执行导航
    5. 返回纯文本结果给 CLI
           │
           ▼
Claude 读取 stdout，继续下一步
```

## 5.2 浏览器自动化完整数据流

```
$B snapshot -i
    │
    ▼ (编译二进制 ~1ms 启动)
browse/src/cli.ts
    ├── 解析命令行参数 → {command: "snapshot", flags: ["-i"]}
    ├── 读取 ~/.gstack/browse.json → port + token
    ├── 健康检查: GET /health (失败则重启服务器)
    └── POST /command {"command":"snapshot","args":["-i"],"token":"<uuid>"}
           │ HTTP ~1ms
           ▼
browse/src/server.ts (Bun.serve 127.0.0.1)
    ├── validateToken() → TokenInfo (isRootToken 或 scoped token)
    ├── checkScope(tokenInfo, "snapshot") → allowed/denied
    ├── checkDomain(tokenInfo, currentUrl) → allowed/denied
    ├── checkRate(tokenInfo) → allowed/retryAfter
    ├── 如果是 DOM_CONTENT_COMMANDS → markHiddenElements(page) 反注入扫描
    ├── handleMetaCommand("snapshot", ...) → 调用 snapshot.ts
    │
    ▼ (CDP via Playwright ~50-150ms)
browse/src/snapshot.ts
    ├── page.accessibility.snapshot() → ARIA 树
    ├── 按序分配 ref: @e1, @e2, @e3...
    │   (规则: getByRole(role, {name}).nth(index))
    ├── BrowserManager.refMap.set("e1", {locator, role, name})
    └── 返回注解的文本树
           │
           ▼ (如果 sidebar agent 调用)
content-security.ts (L1-L3 安全层)
    ├── L1: datamarkContent(text) → 零宽字符水印
    ├── L2: markHiddenElements() → 检测 opacity<0.1, font-size<1px
    ├── L3: ARIA_INJECTION_PATTERNS 正则扫描
    └── wrapUntrustedContent(result, url) → 边界信封包装
           │
           ▼
返回文本给 CLI → stdout → Claude
```

## 5.3 技能调用完整流程（以 /ship 为例）

```
Step 1: 发现 SKILL.md
    Claude Code 搜索 ~/.claude/skills/
    找到 ship/SKILL.md (由 ship/SKILL.md.tmpl 生成)

Step 2: 模板处理管道 (gen-skill-docs.ts)
    ship/SKILL.md.tmpl
    ├── 读取 frontmatter: {name, preamble-tier:4, version, description, allowed-tools}
    ├── 处理 voice-triggers → 追加到 description
    ├── 替换 {{PLACEHOLDER}} 占位符:
    │   ├── {{PREAMBLE}} → generatePreamble(ctx) (preamble.ts)
    │   │   ├── T1: generatePreambleBash → 运行 bash: 读取 config, session, 遥测
    │   │   ├── T2: generateAskUserFormat, generateWritingStyle...
    │   │   ├── T3: generateRepoModeSection...
    │   │   └── T4: 全部 (ship 是 tier 4)
    │   ├── {{BASE_BRANCH_DETECT}} → PR/main 分支检测脚本
    │   ├── {{TEST_COVERAGE_AUDIT_SHIP}} → 测试覆盖率审计 bash
    │   └── {{CHANGELOG_WORKFLOW}} → CHANGELOG 编辑规则
    └── 写出 ship/SKILL.md

Step 3: Claude 执行 (运行时)
    SKILL.md 就是 Claude 的指令文档
    ├── 步骤 0: 运行 Preamble bash 代码块
    │   ├── 检查更新 (gstack-update-check)
    │   ├── 会话跟踪 (touch ~/.gstack/sessions/$PPID)
    │   ├── 读取 config: PROACTIVE, EXPLAIN_LEVEL, QUESTION_TUNING...
    │   ├── 读取 learnings (gstack-learnings-search)
    │   └── 写遥测 (~/.gstack/analytics/skill-usage.jsonl)
    ├── 步骤 1-N: 按 SKILL.md 指令执行
    └── 完成状态:
        ├── gstack-learnings-log '{...}' (如有发现)
        └── 遥测日志 (gstack-telemetry-log)
```

## 5.4 E2E 测试数据流

```
bun run test:evals
    │
    ▼
test/skill-e2e.test.ts
    ├── diff-based 选择: selectTests(changedFiles, E2E_TOUCHFILES, GLOBAL_TOUCHFILES)
    └── 每个 E2E 测试体:
        1. 创建临时工作目录 (os.tmpdir())
        2. 只提取需要的 SKILL.md 片段（非整个文件，防止 token 浪费）
        3. 调用 runSkillTest(prompt, workingDirectory, ...)
           │
           ▼
test/helpers/session-runner.ts: runSkillTest()
    ├── spawn: claude -p \
    │     --model claude-sonnet-4-6 \
    │     --output-format stream-json \
    │     --verbose \
    │     --dangerously-skip-permissions \
    │     --max-turns 15 \
    │     --allowed-tools Bash Read Write
    ├── 流式读取 stdout NDJSON:
    │   ├── type=assistant → 计 turns + tool_calls
    │   ├── type=tool_result → 记录输出
    │   └── type=result → 最终结果
    └── 返回: {toolCalls, output, transcript, costEstimate, model, ...}
           │
           ▼
test/helpers/llm-judge.ts: judge() 或 outcomeJudge()
    ├── callJudge(prompt) → Anthropic SDK (claude-sonnet-4-6)
    ├── 评估维度:
    │   ├── doc 质量: clarity/completeness/actionability (1-5)
    │   ├── 检测率: planted bugs detected/missed/false_positives
    │   └── 姿态: axis_a/axis_b (模式特定, 1-5)
    └── 返回结构化 JSON
           │
           ▼
test/helpers/eval-store.ts: EvalCollector
    ├── 累积每个 test entry
    ├── 写出到 ~/.gstack/projects/{slug}/evals/{version}-{branch}-{tier}-{ts}.json
    └── 自动比较前一次运行 (eval:compare)
```

## 5.5 配置与状态文件流

```
用户环境
    │
    ├── ~/.gstack/config.yaml          ← 全局配置 (gstack-config read/write)
    ├── ~/.gstack/browse.json          ← browse 守护进程状态 (pid, port, token)
    ├── ~/.gstack/sessions/$PPID       ← 会话活跃标记 (touch 文件)
    ├── ~/.gstack/analytics/           ← 技能使用遥测 JSONL
    ├── ~/.gstack/security/            ← 安全日志 (attempts.jsonl, device-salt)
    ├── ~/.gstack/models/              ← ML 模型缓存 (testsavant, deberta)
    │
    └── ~/.gstack/projects/{slug}/
        ├── learnings.jsonl            ← 运营学习数据库
        ├── evals/                     ← E2E 评测结果历史
        └── ceo-plans/                 ← 设计文档 (本地)

项目目录
    ├── CLAUDE.md                      ← 项目配置 (测试命令、部署命令等)
    └── .gstack/                       ← 项目级配置 (可选)
```
