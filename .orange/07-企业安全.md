# 07 企业安全

## 概览

gstack 构建了业界领先的 AI Agent 安全架构，包括：双监听器隔离、多层令牌体系、6 层提示注入防御。

---

## 7.1 双监听器架构 (v1.6.0.0+)

```
                    本地进程
                        │
              ┌─────────┴─────────┐
              ▼                   ▼
    本地监听器                  隧道监听器
    127.0.0.1:LOCAL_PORT       127.0.0.1:TUNNEL_PORT
    (永久绑定)                  (懒加载, 仅 pair-agent 时)
              │                   │
              │                   └─→ ngrok tunnel → 互联网
              │
    完整 API 表面:             受限 API 表面:
    /health (token bootstrap)  /connect (速率限制 300/min)
    /command (root 或 scoped)  /command (仅 scoped token + 26 命令白名单)
    /cookie-picker             /sidebar-chat
    /inspector/*               其他 → 404
    /welcome
    /refs
    /sse-session
    /pty-session
    /token, /pair, /tunnel/*
```

**安全属性:**
- 隔离基于物理 TCP 端口，而非 header 检查（ngrok header 行为不稳定）
- 根令牌通过隧道发送 → 403
- 隧道拒绝日志: `~/.gstack/security/attempts.jsonl`（速率上限 60次/分钟，防止磁盘 DoS）

## 7.2 令牌体系

```
根令牌 (root token)
    │ crypto.randomUUID()，写入 browse.json (mode 0o600)
    │ 启动时生成，服务器内存持有
    │
    ├── POST /token (只有 root 可调用)
    │   └──▶ 作用域令牌 (scoped session token)
    │         prefix: "gsk_sess_" + 24 random bytes
    │         scopes: ['read', 'write', 'admin', 'meta', 'control'] 子集
    │         domains: glob 模式白名单 (可选)
    │         tabPolicy: 'own-only' | 'shared'
    │         rateLimit: N req/sec (0 = 无限制)
    │         expiresAt: 默认 24 小时
    │         commandCount: 计数器
    │
    ├── POST /pair (只有 root 可调用，pair-agent 场景)
    │   └──▶ 一次性设置密钥 (setup key)
    │         prefix: "gsk_setup_" + 24 random bytes
    │         过期: 5 分钟
    │         usesRemaining: 1
    │
    ├── POST /connect (setup key 兑换)
    │   └──▶ 会话令牌 (同上)
    │         幂等: 若该 setup key 已换过且 commandCount=0，返回同一 token
    │
    └── POST /sse-session (只有 root 可调用)
        └──▶ SSE 会话 Cookie (gstack_sse)
              token: 32 random bytes, base64url
              HttpOnly + SameSite=Strict
              TTL: 30 分钟
              仅对 /activity/stream 和 /inspector/events 有效
              绝不可用于 /command (模块边界隔离)
```

**PTY 会话令牌** (`pty-session-cookie.ts`):
- 专为 WebSocket PTY 连接设计
- 通过 `POST /pty-session` 铸造
- `terminal-agent.ts` 在 WebSocket 握手时验证

**关键模块边界:** `sse-session-cookie.ts` 不导入 `token-registry.ts`，这是架构约束，不可破坏。

## 7.3 提示注入防御 (6 层安全栈)

| 层级 | 模块 | 位置 | 机制 |
|------|------|------|------|
| L1 | `content-security.ts` | server + agent | 数据标记: 零宽字符水印，每 3 句注入一次 |
| L2 | `content-security.ts` | server + agent | 隐藏元素剥离: opacity<0.1, font-size<1px, color=background |
| L3 | `content-security.ts` | server + agent | ARIA 注入正则 (7 种模式) + URL 黑名单 + 信封包装 |
| L4 | `security-classifier.ts` | sidebar-agent only | TestSavantAI BERT-small ONNX (112MB, int8 量化, 本地运行) |
| L4b | `security-classifier.ts` | sidebar-agent only | Claude Haiku transcript 分类器 (对话级别分析) |
| L5 | `security.ts` | server + agent | 金丝雀令牌: 随机 token 注入系统提示，检测泄露 |
| L6 | `security.ts` | server + agent | 集成判决 (combineVerdict): 阈值投票规则 |

**重要约束:** `security-classifier.ts` 不能从编译的 browse binary 导入。`@huggingface/transformers` v4 需要 `onnxruntime-node`，从 Bun 编译临时目录 dlopen 失败。只有 `security.ts`（纯字符串操作）可在 `server.ts` 中安全使用。

## 7.4 集成判决规则 (BLOCK 条件)

```
判决阈值:
  BLOCK: 0.85    (单层足够高时，单层即可 BLOCK)
  WARN:  0.60    (跨层确认阈值，两层都 >= 0.60 → BLOCK)
  LOG_ONLY: 0.40 (触发 transcript classifier 的最低阈值)
```

**BLOCK 触发条件:**
1. 金丝雀令牌泄露 → 立即 BLOCK（确定性，不走投票）
2. 单层 content classifier >= 0.85（`SOLO_CONTENT_BLOCK`）→ BLOCK
3. ML content classifier + transcript classifier 都 >= WARN(0.60) → BLOCK（`ensemble_agreement`）

**Transcript 分类器特殊规则:**
- `meta.verdict='block'` + confidence >= 0.40 → block-vote
- `meta.verdict='warn'` → 仅 warn-vote（不计入 BLOCK）
- `meta.verdict='safe'` → 无投票
- 旧版无 meta.verdict → confidence >= WARN 时 warn-vote，永不 block-vote

**环境控制开关:**
```bash
GSTACK_SECURITY_OFF=1            # 关闭 ML 扫描（金丝雀仍然注入）
GSTACK_SECURITY_ENSEMBLE=deberta # 启用 DeBERTa-v3 (721MB，首次运行下载)
                                 # 启用时: 需 2-of-3 ML 分类器同意
```

## 7.5 WebSocket 认证

```
Chrome Extension (sidebar)
    │
    │ new WebSocket(url, [token])
    │ ──── Sec-WebSocket-Protocol: <token> ────▶ browse server
    │                                                │
    │                                      terminal-agent.ts
    │                                      validateToken(token from protocol header)
    │                                                │
    │                                      MUST echo back:
    │ ◀── 101 Switching Protocols ─────────
    │     Sec-WebSocket-Protocol: <token>
    │
    │ (Chromium: 如果服务器不 echo 协议，立即关闭连接)
```

**为什么用 Sec-WebSocket-Protocol 而非 Cookie:**
浏览器在 WebSocket upgrade 请求中无法设置 `Authorization` header，但可以设置 `Sec-WebSocket-Protocol`。Cookie (`gstack_pty`) 保留作为非浏览器调用方的回退。

## 7.6 安全相关文件

| 文件 | 功能 |
|------|------|
| `browse/src/content-security.ts` | L1-L3: 数据标记、隐藏元素剥离、ARIA 注入检测 |
